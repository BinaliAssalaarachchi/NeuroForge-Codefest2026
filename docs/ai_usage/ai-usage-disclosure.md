# AI Usage Disclosure

Per the SLIIT Codefest 2026 AI Competition AI Usage Policy (Section 4.1), this document discloses every AI tool used during development of NeuroForge's Intelligent Document Assistant, what each was used for, and which decisions were made by the team rather than the tool. Honest disclosure carries no penalty - omission or misrepresentation does.

**Note:** This disclosure covers AI tools used to *build* the project (coding assistants, chat models used for planning/docs). It is separate from Gemini Pro and Voyage AI, which are *part of the product itself* (the reasoning and embedding models our assistant calls at runtime) - those are documented in `docs/architecture.md` and `docs/decisions.md`, not here.

---

## Tools Used During Development

### 1. Antigravity (Google)
- **Used for:**
  -Early-stage development, at the start of the competition window, before the team settled on the final architecture — initial project scaffolding, exploratory prototyping of the retrieval pipeline, and early experimentation with the ingestion pipeline (DocumentParser/Chunker) design.
What the team decided, not the AI:
  -The decision to move from this early prototyping phase into the final hybrid BM25 + dense retrieval architecture and the iterative agent loop was made by the team based on what worked and didn't during this exploratory phase — documented as part of the design evolution in docs/limitations.md.
  -Code and structure from this phase were reviewed and substantially reworked as the team's understanding of the problem matured; not all early scaffolding survived into the final submission.
- **Chat log:** exported to[[ docs/ai_usage/chat-logs/antigravity-session.txt]](NeuroForge-Codefest2026/docs/ai_usage/chat-log/antigravity-session.txt)

### 1. Codex (OpenAI)
- **Used for:**
  - Implementation support while writing the system's code - the offline ingestion pipeline (DocumentParser, Chunker), the hybrid retrieval components (BM25 Search, Dense Vector Search, Reciprocal Rank Fusion), the iterative agent (HumanLikeSearchAgent, SearchState, CombinedEvaluator, AnswerGenerator), and the application interfaces (Streamlit `app.py`, CLI `main.py`, `scripts/query_search.py`).
  - Debugging, boilerplate generation, and refactoring suggestions during implementation.
- **What the team decided, not the AI:**
  - The overall system architecture - hybrid BM25 + dense retrieval fused via Reciprocal Rank Fusion, the iterative search-and-evaluate loop, and the confidence ≥ 7 stopping gate — was designed by the team, not generated by Codex in one pass.
  - The switch from OpenAI's API (hit usage limits) to Gemini's free tier (inconsistent answers, its own rate limits) to Gemini Pro was a decision driven by the team's own testing, not a suggestion from any AI tool.
  - All Codex-generated code was reviewed, tested, corrected, and in many cases substantially rewritten by team members before being committed — see commit history for the iterative refinement this involved.
- **Chat log:** exported to[[`docs/ai_usage/chat-logs/codex-coding-session.txt`]](docs/ai_usage/chat-logs/codex-coding-session.txt)

### 2. Claude (Anthropic)
- **Used for:**
  - Drafting and structuring project documentation: `README.md`, `docs/architecture.md`, `docs/decisions.md`, `docs/limitations.md`, and this disclosure file.
  - Turning our architecture diagram into written architecture documentation.
  - Suggesting a team contribution/role breakdown, which the team then adapted (see Team Roles note below).
- **What the team decided, not the AI:**
  - The actual system design (architecture, retrieval strategy, stopping logic) was given to Claude *after* the team built it — Claude helped document it clearly, it did not design the system.
  - All bracketed/placeholder content in template docs was reviewed and replaced with the team's actual figures, thresholds, and test results before submission.

## Runtime AI Services (Part of the Product — Documented in Full in `docs/architecture.md`)

For completeness, the assistant itself calls the following AI services at runtime — these are the product's components, not development tools, but are listed here for transparency:

| Service | Role in the system |
|---|---|
| **Gemini Pro (Google API)** | Reasoning for HumanLikeSearchAgent, CombinedEvaluator's confidence scoring, and AnswerGenerator's final synthesis |
| **Voyage AI API** | Document and query embeddings for the ChromaDB dense retrieval index |

The team's own iterative-agent design, hybrid retrieval strategy, confidence-gated stopping logic, and source-attribution approach are original engineering work built around these models — the models generate text/embeddings, but the *system design* is ours.

## Development Process Summary

- Development ran across the full competition window (28 August – 9 September 2026); commit history in the Git repository reflects this timeline.
- AI tools were used iteratively throughout - not as a single one-shot "generate the solution" prompt. Early approaches were tested and revised (e.g. moving from single-pass retrieval to the iterative agent loop, from dense-only to hybrid BM25+dense retrieval, and switching LLM providers after hitting real usage limits) - see `docs/limitations.md` for the abandoned approaches this process ruled out.
- Every team member can explain, justify, and modify any part of the submission, including sections where Codex or Claude assisted, per Section 4.1's requirement.

## Team Roles & Contributions

The team worked collaboratively across the project rather than working in strict, siloed roles - all four members contributed across most areas of the system. For the purposes of the submission report's contribution breakdown, work is grouped into four areas (see `README.md` → Team, and `submission_report.pdf`):

2. **Agentic Reasoning & Orchestration** - the search loop, SearchState, CombinedEvaluator, stopping logic
3. **Answer Synthesis, Grounding & Evaluation** - AnswerGenerator, source attribution, testing against `sample_questions.json`
4. **System Integration, Documentation & Submission** - interfaces, docs, diagrams, disclosure, demo video
